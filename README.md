라이브: **https://dash199446-design.github.io/pano-hire/**

지원자 카드 대시보드 + 인물별 상세 + 면접 채점 + 비교표. 서버 없는 정적 사이트(GitHub Pages).

## 화면

| 경로 | 내용 |
|---|---|
| `#/` | **홈 대시보드** — 사진·요약·점수 카드 그리드. 통계 클릭으로 필터, 점수/경력/이름순 정렬, 검색 |

| `#/guide` | **평가 기준** — 면접 진행 순서 · 공통 케이스 · 질문 가이드 · 채점 앵커 |

## 파일

```
index.html     셸 + 전체 CSS
app.js         렌더링 · 상태 · 채점 · 내보내기
data.js        지원자 프로필 + 평가 기준 (window.D)
results.json   공용 면접 기록 (커밋본)
img/<id>.jpg   증명사진 300×400 (이력서 PDF에서 추출)
```

## 기록이 저장되는 방식

두 곳을 후보 단위로 병합합니다.

- **`results.json`** — 저장소에 커밋된 공용 기록. 누가 열어도 보입니다.
- **`localStorage`** — 채점하는 사람의 브라우저에만 남는 기록.

같은 후보에 둘 다 있으면 `_ts`(레코드별 타임스탬프)가 최신인 쪽이 이깁니다.
밀려난 기록이 있으면 상단에 경고가 뜨고 콘솔에 목록이 찍힙니다.

### 내 채점을 모두에게 보이게 하려면
1. 상단 **「기록 내보내기」** → JSON 파일 다운로드
2. 그 파일을 전달 → `results.json`으로 커밋 → 자동 재배포

### 주의
- localStorage는 **브라우저마다 따로**입니다. 다른 PC에서는 보이지 않습니다.
- 시크릿 모드·용량 초과 등으로 저장에 실패하면 상단에 ⚠ 경고가 뜹니다. 그때는 바로 JSON으로 내보내세요.
- `⋯` 메뉴의 **「기록 파일에 자동 저장」**(크롬/엣지)을 쓰면 입력이 지정한 JSON 파일에도 계속 저장됩니다. 단 새로고침하면 연결이 끊깁니다.

## 지원자 추가 방법

`data.js`의 `CANDIDATES` 배열에 객체를 추가합니다.

```js
{
  id: 'hong_gd',            // 영소문자+언더스코어, 고유
  photo: 1,                 // img/hong_gd.jpg 가 있을 때만
  name: '홍길동', gender: '남', birth: '1995년생', age: '만 30세',
  phone: '010-0000-0000', email: 'x@y.com', addr: '서울 …',
  edu: ['○○대학교 ○○학과 졸업 · 2014.03–2018.02'],
  total: '5년 2개월', status: '재직 중 (○○, 2024.01~)', salary: '면접 후 결정',
  files: '이력서 · 포트폴리오',
  summary: '카드에 보이는 2~4문장 요약',
  career: [['2024.01 – 현재', '회사 · 직책', '한 일과 성과']],
  strengths: ['…'], concerns: ['…'], questions: ['…'],
}
```

사진은 `img/<id>.jpg` (3:4 비율, 300×400 권장)로 넣고 `photo: 1`을 붙입니다. 없으면 이름 이니셜 카드가 자동 생성됩니다.

## 평가 기준

가중 점수 = Σ(점수/5 × 가중치), 100점 만점.

| 항목 | 배점 |
|---|---|
| 로직 설계 사고 | 20 |
| 개발자·디자이너·경영진 협업 | 15 |
| AI 활용 | 15 |
| ★ 면접관 직감 | 20 |
| 사업적 사고 | 10 |
| 인성·컬처핏 | 10 |
| 문제 해결 | 5 |
| 커뮤니케이션 | 5 |

판정: **85+** Strong Hire · **70–84** Hire · **55–69** Lean No · **55 미만** No Hire
