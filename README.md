## 대시보드 필터 (홈 상단 숫자를 클릭)

| 필터 | 조건 |
|---|---|
| 전체 | 전원 |
| 면접 예정 | 아직 채점이 없고 결과도 없는 사람 |
| 1차 면접 완료 | 채점이 하나라도 있고 아직 결과가 없는 사람 |
| ★ 대표님 면접 대상 | 2차 추천 = **추천** 이고 결과가 아직 없는 사람 |
| 최종 합격 | 결과 = 최종 합격 |
| 탈락 · 종료 | 1차 탈락 · 최종 탈락 · 사퇴 · 면접 미참여 |

**면접일**은 상세 페이지의 `면접` 날짜 입력에서 정해지고, 카드 사진 왼쪽 아래에 `9/12(금) 면접`으로 표시됩니다. 앞으로의 날짜면 흰 배지로 `면접 예정`이 붙습니다. 정렬에 **면접일순**이 있습니다.

## 전형 결과 (최종 탈락 표시)

결과는 **홈 대시보드 카드 아래 버튼**에서 바로 누를 수 있고, 상세 페이지 `07 종합 판정` 안에도 같은 버튼이 있습니다.

| 결과 | 카드 표시 |
|---|---|
| 1차 탈락 | 빨간 띠 + 흑백 처리 |
| 최종 합격 | 초록 띠 + 초록 테두리 |
| 최종 탈락 | 빨간 띠 + 흑백 처리 |
| 지원자 사퇴 | 회색 띠 + 흑백 처리 |

같은 버튼을 한 번 더 누르면 결과가 취소되고 「진행 중」으로 돌아갑니다. 사유 메모는 상세 페이지에서 입력합니다.

## 파일

```
index.html     셸 + 전체 CSS
config.js      실시간 공유 저장소(Supabase) 설정 — 비어 있으면 자동으로 꺼짐
app.js         렌더링 · 상태 · 채점 · 동기화 · 내보내기
data.js        지원자 프로필 + 평가 기준 (window.D)
results.json   공용 면접 기록 (커밋본)
img/<id>.jpg   증명사진 300×400 (이력서 PDF에서 추출)
```

## 기록이 저장되는 방식

세 곳을 후보 단위로 병합합니다. 같은 후보에 여럿 있으면 `_ts`(레코드별 타임스탬프)가 최신인 쪽이 이깁니다.

1. **Supabase** — 실시간 공용 저장소. **켜져 있으면 링크를 연 모든 사람이 같은 기록을 봅니다.**
2. **`results.json`** — 저장소에 커밋된 공용 기록.
3. **`localStorage`** — 보는 사람의 브라우저에만 남는 기록.

`config.js`가 비어 있으면 1번이 꺼지고 예전처럼 2 ⊕ 3 으로만 동작합니다. 그때는 홈 상단에 「이 브라우저에만 저장됩니다」 경고가 뜹니다.

### 실시간 공유 켜기 (5분)

1. <https://supabase.com> 가입 → **New project** (무료 플랜)
2. 왼쪽 **SQL Editor** → 아래 붙여넣고 **Run**

```sql
create table interviews (
  id   text primary key,
  data jsonb not null,
  ts   timestamptz not null default now()
);
alter table interviews enable row level security;
create policy "anon read"   on interviews for select using (true);
create policy "anon insert" on interviews for insert with check (true);
create policy "anon update" on interviews for update using (true) with check (true);
```

3. **Settings → API** 에서 두 값을 복사
   - `Project URL` (예: `https://abcdefgh.supabase.co`)
   - `anon` `public` 키 (공개용이라 노출돼도 됩니다)
4. `config.js`의 `url` · `key`에 넣고 커밋 → 재배포

켜지면 상단 칩이 `✓ 실시간 공유 저장 켜짐` → 입력할 때마다 `✓ 모두에게 공유됨`으로 바뀝니다. 다른 사람 변경사항은 20초마다(그리고 탭으로 돌아올 때) 자동으로 가져옵니다.

> RLS 정책이 `anon`에게 열려 있습니다. **링크를 아는 사람은 기록을 수정할 수 있습니다.** 채용 종료 후에는 테이블을 지우세요.

### 주의
- Supabase가 꺼져 있으면 localStorage는 **브라우저마다 따로**입니다. 다른 PC에서는 보이지 않습니다.
- 저장에 실패하면 상단에 ⚠ 경고가 뜹니다. 그때는 바로 **「기록 내보내기」**로 JSON을 받아두세요.
- 내 채점을 커밋본으로 굳히려면: **「기록 내보내기」** → 그 파일을 `results.json`으로 커밋.
- `⋯` 메뉴의 **「기록 파일에 자동 저장」**(크롬/엣지)을 쓰면 입력이 지정한 JSON 파일에도 계속 저장됩니다. 단 새로고침하면 연결이 끊깁니다.

## 지원자 추가 방법

`data.js`의 `CANDIDATES` 배열에 객체를 추가합니다.

```js
{
  id: 'hong_gd',            // 영소문자+언더스코어, 고유
  photo: 1,                 // img/hong_gd.jpg 가 있을 때만
  name: '홍길동', gender: '남', birth: '1995년생', age: '만 30세',
  phone: '010-0000-0000', email: 'x@y.com', addr: '서울 …',
  edu: ['○○대학교 ○○학과 졸업 · 2014.03–2018.02'],
  total: '5년 2개월', status: '재직 중 (○○, 2024.01~)', salary: '면접 후 결정',
  files: '이력서 · 포트폴리오',
  summary: '카드에 보이는 2~4문장 요약',
  career: [['2024.01 – 현재', '회사 · 직책', '한 일과 성과']],
  strengths: ['…'], concerns: ['…'], questions: ['…'],
}
```

사진은 `img/<id>.jpg` (3:4 비율, 300×400 권장)로 넣고 `photo: 1`을 붙입니다. 없으면 이름 이니셜 카드가 자동 생성됩니다.

## 평가 기준

가중 점수 = Σ(점수/5 × 가중치), 100점 만점.

| 항목 | 배점 |
|---|---|
| 로직 설계 사고 | 20 |
| 개발자·디자이너·경영진 협업 | 15 |
| AI 활용 | 15 |
| ★ 면접관 직감 | 20 |
| 사업적 사고 | 10 |
| 인성·컬처핏 | 10 |
| 문제 해결 | 5 |
| 커뮤니케이션 | 5 |

판정: **85+** Strong Hire · **70–84** Hire · **55–69** Lean No · **55 미만** No Hire
